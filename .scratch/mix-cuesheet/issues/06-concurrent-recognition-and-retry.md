# 06：並行辨識與限流重試

**What to build:** 辨識請求改成有並行上限的同時送出，分析一支混音影片的時間明顯縮短。辨識結果不按順序回來時，畫面上的曲目表仍依開始時間排序，待處理的片段也不會被誤判為未辨識。Shazam 暫時限流（429）時，系統會以指數退避自動重試；重試用完，或遇到其他辨識錯誤時，該片段視為無結果，任務照常完成，使用者仍然拿得到其他片段的結果

請參考 spec 的「分析任務執行器」模組和設定常數

**Blocked by:** 05：完整合併規則

**Status:** ready-for-agent

- [ ] 辨識請求的同時進行數以設定常數控制（2～3 之間取一個值）
- [ ] 辨識器遇到限流時丟出可以辨別的限流錯誤
- [ ] 遇到限流錯誤時以指數退避重試，最多重試設定常數指定的次數
- [ ] 重試用完或遇到其他辨識錯誤時，該片段視為無結果，任務繼續執行並正常完成
- [ ] 退避的等待機制可以注入，測試時不需要真的等待
- [ ] 辨識結果亂序完成時，每次送出的曲目表快照仍依開始時間排序
- [ ] pytest 透過分析任務執行器驗證：限流後重試成功、重試用完後視為無結果且任務正常完成、亂序完成時快照仍正確排序且待處理片段不會被當成未辨識
- [ ] 手動驗證：分析一支真實的混音影片，速度比逐段辨識快，且結果與逐段辨識一致
