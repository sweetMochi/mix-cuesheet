# 05：完整合併規則

**What to build:** 曲目表依照 spec 的完整合併規則呈現。在使用情境中，同一首曲目在一支混音裡重複出現的機率非常低，所以每首曲目在曲目表中只會出現一次，開始時間取整支影片中最早一次命中的時間。轉場時兩首交替被辨識到，或播放途中有一段被誤判成別首，都不會讓同一首歌重複出現。整支影片中只命中 1 次的曲目仍然列出，但會加上「僅命中 1 次」標記。連續 2 個以上的無結果片段合併成一列「未辨識」，並顯示時間區間；單一個無結果片段一律忽略。分析進行中時，還沒辨識完的片段不會被當成未辨識。前端表格會顯示標記和未辨識列

請參考 spec 的「合併規則」模組

**Blocked by:** 04：分析流程畫面

**Status:** ready-for-agent

- [ ] 以 Shazam 回傳的曲目識別碼判斷是否為同一首
- [ ] 整支影片中命中同一首的所有片段都併入同一列，開始時間取最早一次命中的片段起始時間
- [ ] 同一首被無結果片段或其他曲目隔開後再出現時仍只有一列（例如 A、A、B、A、B、B 只產生 A 和 B 兩列，開始時間各取第一次命中的時間）
- [ ] 整支影片中總命中次數只有 1 次的曲目列保留，並帶有「僅命中 1 次」標記
- [ ] 單一個無結果片段不產生「未辨識」列
- [ ] 連續 2 個以上的無結果片段合併成一列「未辨識」，時間區間從第一個無結果片段的起始時間，到緊接在最後一個無結果片段之後的片段起始時間（或影片結尾）
- [ ] 曲目列與「未辨識」列一起依開始時間排序
- [ ] 尚未完成辨識的片段視為待處理，不會被當成無結果，也會中斷連續無結果片段的計算
- [ ] 前端以標記顯示「僅命中 1 次」，「未辨識」列顯示時間區間
- [ ] pytest 透過分析任務執行器（注入假的音訊來源和辨識器）驗證以上每一條規則，只檢查輸出的事件和曲目表
