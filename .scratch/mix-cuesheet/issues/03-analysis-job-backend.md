# 03：分析流程後端（tracer bullet）

**What to build:** 透過 API 建立一個分析任務後，後端會實際以 yt-dlp 下載混音影片的音訊、以 FFmpeg 切出片段，再依序逐段送 Shazam 辨識。訂閱任務事件串流（SSE）就能依序收到階段變更（下載中、切割中、辨識中）、辨識進度（n／N）、每完成一段就重新計算的曲目表快照，以及最後的完成事件。下載失敗時會收到錯誤事件，訊息使用者看得懂。不論完成或出錯，任務專屬的暫存資料夾都會被刪除

這張只做最簡單的合併：連續辨識到同一首曲目時合併成一列，開始時間取第一次命中的片段起始時間。辨識逐段依序進行，不並行、不重試、不支援取消，這些會在後續 ticket 加入。這張 ticket 只透過 API 驗證，前端畫面在下一張

請參考 spec 的「分析任務執行器」「音訊來源」「辨識器」模組和 API 契約中的「建立分析任務」「任務事件串流」

**Blocked by:** 02：網址驗證與影片預先解析

**Status:** ready-for-agent

- [ ] 分析任務執行器接受影片資訊、設定常數、音訊來源和辨識器，輸出一連串事件；音訊來源和辨識器都是可以替換的介面
- [ ] 切段使用 02 的切段規劃，進度事件的 N 與預估片段數一致
- [ ] 音訊來源的實際實作以 yt-dlp 下載最佳音質的音訊到任務暫存資料夾，再以 FFmpeg 依起始秒數和長度切出片段
- [ ] 辨識器的實際實作使用 shazamio，回傳曲目識別碼、演出者、曲名、Shazam 連結和封面網址（封面可能為空值），沒有結果時回傳無結果；會正確關閉底層 HTTP session，不會出現 Unclosed client session 警告
- [ ] 連續命中同一首曲目時合併成一列，開始時間取第一次命中的片段起始時間
- [ ] 曲目表快照中每個曲目列附上格式化後的開始時間（未滿 1 小時用 `MM:SS`，1 小時以上用 `H:MM:SS`），前端不需要自己實作時間格式
- [ ] 建立分析任務端點輸入影片 ID，回傳任務 ID
- [ ] 任務事件串流以 SSE 推送階段變更、辨識進度、曲目表快照、完成和錯誤事件
- [ ] 下載失敗時送出錯誤事件，訊息使用者看得懂，並提示可以先更新系統上的 yt-dlp
- [ ] 任務完成或出錯後，暫存資料夾都會被刪除
- [ ] pytest 注入假的音訊來源和假的辨識器，驗證：片段起始時間與數量、連續命中合併、進度事件的 N、下載錯誤時的錯誤事件、完成與錯誤後暫存資料夾被刪除
- [ ] 手動驗證：用一支真實的混音影片建立任務，透過 SSE 收到完整的事件流程和合理的曲目表
